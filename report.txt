WEEK 2 — Authentication System & Role-Based Access Control
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  • Architected a stateless JWT-based authentication system with secure httpOnly
    cookie handling, implementing separate access flows for Admin and Employee
    roles.

  • Built the full authentication API (/register, /login, /logout, /verify-otp)
    with bcrypt password hashing (salt rounds: 10) and middleware-level route
    protection using verifyToken.

  • Designed and implemented OTP-based forgot-password flow using Nodemailer
    with Gmail SMTP, including token expiry logic and a secure reset endpoint.

  • Developed React authentication context (AuthContext) with persistent session
    management, protected route wrappers, and automatic redirection based on
    user role.

  • Implemented an access request system allowing new employees to submit join
    requests that admins approve or reject, eliminating the need for manual
    account provisioning.

  • Enforced server-side role validation on all API routes (isAdmin middleware),
    ensuring zero privilege escalation vulnerabilities between employee and admin
    endpoints.

WEEK 3 — Inventory Management Module
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  • Designed and implemented the Chemical Mongoose model with fields for name,
    category, quantity, unit, purchase price, sale price, expiry date, and
    status — with pre-save hooks for automatic status transitions
    (Available → Low Stock → Out of Stock).

  • Built a complete CRUD REST API for chemical inventory with Express Router,
    including query-based filtering by category, status, and expiry range,
    serving paginated responses for performance.

  • Developed the Inventory UI in React with a dynamic data table, real-time
    status badge rendering (color-coded), and a modal-driven Add/Edit/Delete
    workflow with full form validation.

  • Implemented an expiry alert system that flags chemicals expiring within 30
    days, surfaced as a dedicated "Alerts" panel on the Admin Dashboard with
    visual severity indicators.

  • Integrated stock status auto-calculation logic on every quantity update —
    ensuring the UI and database always reflect the true stock state without
    manual intervention.

  • Added a "Stock Movement" activity log that records every update event (who
    updated, what quantity changed, timestamp) for full traceability of chemical
    stock changes.

WEEK 4 — Employee Dashboard & Stock Update Workflow
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  • Built a dedicated Employee Portal with a role-scoped sidebar navigation,
    ensuring employees only access screens relevant to their permissions (no
    inventory deletion, no financial data).

  • Engineered a consumption-based stock update modal where employees input
    "Quantity Sold," and the system computes the remaining stock and triggers
    automatic status recalculation.

  • Implemented the UpdateStockModal with mandatory payment method capture
    (Cash / Credit / UPI / Pending) and sale amount input, persisting a linked
    Sale record atomically with the stock update.

  • Built the "My Sales" view for employees — a personal sales ledger filtered
    by the authenticated user, displaying transaction history with chemical name,
    amount, payment method, and timestamp.

  • Added a "Recent Updates" feed on the employee dashboard showing the last 10
    stock operations performed by that specific employee, rendered with relative
    timestamps (e.g., "2 hours ago").

  • Enforced a one-time payment status constraint — once a sale's payment status
    is marked as received, the employee cannot modify it further, preserving
    financial data integrity.

  • Designed the Task Mongoose model with fields for title, description, assigned
    employee (ref: User), deadline, priority, and a status state machine
    (Pending → Accepted → In Progress → Completed / Reverted).

  • Built the full Task CRUD API with population of employee details on fetch,
    supporting filtering by status, assigned user, and deadline proximity for
    the Admin's task management view.

  • Developed the Admin Task Board UI — a Kanban-inspired layout displaying tasks
    grouped by status with deadline countdowns, color-coded urgency badges, and
    reassignment capability.

  • Implemented the Employee Task Panel where employees can view their assigned

    completed — all triggering real-time status updates in the Admin view.

  • Integrated automated email notification via Nodemailer to alert employees
    instantly when a new task is assigned to them, including task title,
    deadline, and admin instructions in the email body.

  • Added overdue task detection logic — tasks past their deadline without
    completion are automatically highlighted with a warning badge and surfaced
    in a dedicated "Overdue" filter on the admin portal.

  • Designed the AttendanceLog Mongoose model to capture precise login/logout
    timestamps per employee session, with timezone normalization to IST using
    UTC offsets to prevent cross-timezone data inconsistencies.

  • Built attendance recording middleware that automatically creates a login log
    entry on successful authentication and closes the session record on logout —

  • Developed the Admin Attendance Calendar — an interactive calendar UI

    employee login/logout sessions for that day.

  • Built the Employee Attendance View showing personal login history in a
    structured log format with session duration calculation (logout time minus
    login time), providing employees visibility into their own records.

  • Implemented a mandatory "Please Remember to Log Out" overlay enforced at the
    start of every employee session — ensuring clean session termination and
    accurate working hour computation.

  • Configured server-side attendance log segregation from general activity logs,
    using separate database collections to keep attendance data clean, isolated,
    and independently queryable.

  • Built an Employee Activity Log aggregation view for admins, showing a

  • Implemented express-rate-limit middleware on all authentication endpoints
    (/login, /forgot-password, /verify-otp) to throttle brute-force attempts —
    capping at 10 requests per 15-minute window per IP.

  • Added server-side input validation using schema-level Mongoose validators

    that was present in early development.

  • Optimized MongoDB queries across the Sale, Activity, and Attendance
    collections by adding compound indexes on (userId, createdAt) and
    (status, createdAt) — reducing query execution time on large datasets.

  • Separated environment configuration into .env.development and
    .env.production files, preventing accidental use of production credentials
    in local development and improving deployment hygiene.

  • Audited all API routes for missing authentication middleware, securing 3
